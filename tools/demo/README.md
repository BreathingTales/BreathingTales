# 차량 감시 페이지

앱과 별개로 Pleos Virtual Console API(`/vehicle/state`)만 0.2초마다 읽는 페이지입니다. **차 쪽에서 읽은 값**으로 두 가지를 기록합니다. 하나는 연출이 안전 한도 안에 있었는지, 다른 하나는 끝난 뒤 시작 전 값으로 돌아왔는지입니다. 앱 코드를 읽지 않는 독립 검증이라 **제출한 release APK 그대로** 확인할 수 있습니다. 앱 안의 시연 HUD는 debug 빌드 전용입니다.

## 쓰는 법
1. 에뮬레이터를 켜고 PC에서 `adb forward tcp:8088 tcp:8088`을 실행합니다. Virtual Console 상단 `AVD`가 `Enabled`인지 확인합니다.
2. `tools/demo/monitor.html`을 브라우저로 엽니다. 서버는 필요 없습니다. Virtual Console API가 `Access-Control-Allow-Origin: *`를 보냅니다.
3. 이야기를 시작하기 **직전에** `새 시연 (기준 잡기)`를 누릅니다. 이때의 값을 시작 전 상태로 삼습니다.
4. 이야기를 진행합니다. 끝나면 `기록 저장`으로 JSON을 받아 둡니다. 나중에 `기록 열기`로 다시 볼 수 있습니다.

- 이 페이지도 Virtual Console처럼 세션 신호(`POST /browser/session`)를 보냅니다. 그래서 Virtual Console 탭을 가려도 AVD가 꺼지지 않습니다.
- AVD가 꺼지면 빨간 띠로 알립니다. 이때 앱의 차량 명령은 오류 없이 무시됩니다.

### 시트 들썩임까지 보려면
1. 앱의 부모 설정에서 **시트 들썩임**을 켭니다. 기본값은 꺼짐입니다.
2. Virtual Console에서 **조수석을 착석**으로 둡니다. 높이는 맨 위(100)만 아니면 됩니다.
   ```
   curl -X PUT "http://127.0.0.1:8088/vehicle/seat?kind=occupied&area=passenger&value=true"
   curl -X PUT "http://127.0.0.1:8088/vehicle/seat?kind=position&control=height&area=passenger&value=40"
   ```
3. 바람이 거세지는 장면(`wind-strong`)에서 조수석 높이·방석 기울기가 시작 +10 안에서 한 번 올랐다 돌아옵니다. 규칙상 연출마다 최대 3번까지 되풀이할 수 있고, 이 동화의 대본은 한 번입니다.

## 판정 기준
앱의 `SafetyLimits`와 같은 숫자를 `monitor.html` 위쪽에 직접 적어 두었습니다. 앱의 한도를 바꾸면 여기도 고쳐야 합니다.

| 항목 | 기준 |
|---|---|
| 풍량 | 범위 1~8의 80% = 6 이하. 넘으면 ✗를 표시하고, 시작값도 높았으면 함께 적음. 강도 약·중이면 앱 한도는 더 낮지만 여기서는 상한만 봄 |
| 온도 | 영역별로 `max(20, 시작-2) ~ min(26, 시작+2)` 안. 범위 밖 값이 시작값뿐이면 ✓로 따로 표시 |
| 시트 열선 | 1단 이하 |
| 조수석 높이·방석 기울기 | 각각 시작 +10 이하, 시작보다 내려가지 않음. 움직이지 않았으면 "변화 없음"만 적음 (이유는 페이지가 알 수 없음) |
| 시트가 올라갈 때 | Virtual Console 조수석 착석이 "앉음"이고 P·0km/h·문 닫힘이었는지 |
| 등받이·다른 좌석 | 조수석 등받이·앞뒤·허리, 운전석·뒷좌석 시트 값이 바뀌지 않음 |
| 창문 | 변화 없음 |
| 조건이 깨지면 | P·0km/h·문 닫힘이 처음 깨진 뒤 공조·무드등이 기준 값과 같아지기까지 걸린 시간 |
| 지금 값 | 앱이 바꾸는 16개 항목이 기준 값과 같은지. 다르면 항목 이름을 적음 |

API에 없는 정차 조건(주차 브레이크, UX 제한)과 안전벨트는 판정하지 않습니다.

### 판정 문구 원칙
- **읽은 값으로 확인한 것만 씁니다.** "앱이 ~했다", "즉시", "왜 그런지" 같은 말은 판정에 넣지 않습니다. 이 페이지는 누가 값을 바꿨는지 알 수 없습니다.
- 0.2초마다 읽으므로 그 사이의 짧은 변화는 놓칠 수 있습니다. 판정 아래 주석에 항상 적습니다.
- 기준은 「새 시연」을 누른 때의 값입니다. 누르지 않았으면 페이지를 연 때의 값입니다. 이야기 시작 직전에 누르지 않으면 판정이 틀어집니다.
- 배경 지식(예: 에뮬레이터는 기어가 P가 아니면 등 스위치 명령을 거부함)은 "참고"와 확인 날짜를 붙여 따로 적습니다.

## 자체 확인
`selftest/`에 기록 다섯 개가 있습니다. 판정 로직을 고친 뒤 다시 열어 봅니다.

| 열기 | 내용 | 기대 결과 |
|---|---|---|
| `monitor.html?replay=selftest/good` | 만든 기록. 기어 D → 1초 안에 공조·무드등 복원, P로 돌아온 뒤 독서등 복원 | 모두 ✓ |
| `monitor.html?replay=selftest/bad` | 만든 기록. 풍량 7, 온도 25℃, 창문 열림 | ✗ 세 개 |
| `monitor.html?replay=selftest/seat-good` | 만든 기록. 조수석 높이 40→50·기울기 30→40을 세 번, 앉은 채 정차 중 | 시트 판정 모두 ✓ |
| `monitor.html?replay=selftest/seat-bad` | 만든 기록. 높이 55·35, 빈자리에서 올라감, 기어 D에서 올라감, 등받이 바뀜 | 시트 ✗ 네 개 |
| `monitor.html?replay=selftest/real-2026-11-10` | 실제 기록 (1초 간격으로 읽던 이전 버전). release APK, 강도 강, 바람·해님 장면 → 기어 D → P | 풍량 최고 4, 온도 20.5~23.5℃, 독서등은 D 동안 켜진 채였다가 P에서 꺼짐, 끝에 모든 항목이 기준과 같음 |

`?replay=`로 여는 자체 확인은 같은 폴더의 `.js` 파일을 읽으므로, 브라우저에 따라 로컬 파일 접근을 허용해야 합니다. 예를 들어 Edge·Chrome은 `--allow-file-access-from-files` 옵션이 필요합니다.
